# アプリと拡張機能の E2E

このディレクトリには、Electron の画面とプロセス、拡張機能のブラウザ上の挙動を検証するテストがあります。他のテストとの使い分けは [`docs/テスト.md`](../docs/テスト.md) を参照してください。

```powershell
npm run test:e2e         # 全プロジェクトを検証する
npm run test:e2e:flow    # フローだけを検証する
npm run test:e2e:update  # 基準スクリーンショットを更新する
```

実行前に `npm run build --workspace=app` と `npm run build:ext:test` でアプリとテスト用拡張機能をビルドしてください。アプリのビルド成果物がない場合、`scripts/lib-electron-path.cts` がテストの起動を中止します。

## テストプロジェクト

| プロジェクト | 場所 | CI |
| --- | --- | --- |
| `flow` | `e2e/flows/` | `app-tests.yml` で手動実行 |
| `harness` | `e2e/harness/` | `app-tests.yml` で手動実行 |
| `extension` | `e2e/extension/` | `app-tests.yml` で手動実行 |
| `visual` | `e2e/visual/` | 実行しない |

## 基準スクリーンショットをローカルで管理する理由

基準スクリーンショットはこの開発機で撮影し、リポジトリへコミットします。CI では画像を比較しません。この方針は Issue #14 で 2026 年 7 月 29 日に決定しました。

一般的なビジュアルテストでは、開発機や OS による差を避けるため、CI の固定環境で基準スクリーンショットを作成します。このプロジェクトでは、次の理由からローカル環境を基準にしています。

- 単独開発で、開発機と CI はどちらも Windows です。
- Windows デスクトップアプリには、Playwright の公式 Docker イメージを固定環境として利用できません。
- 同じ Windows でも、フォント、GPU、表示設定が異なるとピクセル単位の結果は一致しません。Playwright の既定の接尾辞はどちらも `win32` となるため、そのままでは環境ごとに基準画像を分けられません。
- UI の変更中にローカルで差分を検出できることを優先します。

再検討する条件は、Issue #14 の決定コメントに記録しています。

## スクリーンショットの対象

全面再設計を扱う Issue #154 が進行中のため、ツールバー、チップ帯、サイドバーはまだ変化します。現在のスクリーンショットは、インスペクター、設定ダイアログ、確認ダイアログなどのパネルとダイアログに限定しています。ページ全体ではなく要素単位で撮影し、対象外の UI 変更が差分に混ざらないようにしています。対象の拡大は Issue #154 の完了後に検討します。

## 再現性のために固定する条件

`e2e/lib/harness.ts` が起動時に次の条件を固定します。条件を追加する場合も、このファイルに実装します。

- ウィンドウ内の高さは 800 px です。幅は `e2e/lib/viewport.ts` が `layout-mode.ts` の `WIDE_MIN_PX` から算出します。`flow` はワイドレイアウトを検証するため、起動後の実測でナローレイアウトになった場合は失敗します。
- DPI は `--force-device-scale-factor=1` で固定します。
- テーマは起動前に `config.json` へ書き、OS の設定に依存する `auto` を使いません。
- 表示言語は `ja`、タイムゾーンは `Asia/Tokyo` に固定します。
- フィクスチャは、ID、日時、画像の寸法と色を固定します。実装は `e2e/lib/library.ts` にあります。
- `toHaveScreenshot` の `animations: 'disabled'` でアニメーションを無効にします。

画像差分のしきい値は `maxDiffPixels: 0` です。動く要素がある場合は、しきい値を広げる前に `mask` で比較対象から外します。

## ウィンドウを前面に出さない

テストには表示中のウィンドウが必要ですが、利用者の操作を妨げないように前面へ出しません。`HOLOGRAM_START_INACTIVE=1` でフォーカスを取得せず、ウィンドウを Z オーダーの背面へ移動します。入力は CDP 経由で送るため、フォーカスは不要です。

Chromium が背面ウィンドウの描画を止めないように、Playwright が通常のブラウザへ渡すものと同じ抑制フラグも設定します。

## サンドボックス

各テストは `mkdtemp` で専用の設定ディレクトリとライブラリを作り、終了時に削除します。`HOLOGRAM_SANDBOX=1` ではネイティブメッセージングホストも登録しません。通常の設定ディレクトリ、`~/Hologram/library`、Chrome の登録情報には触れません。

## 既知の失敗

既知のアプリ側の不具合には `test.fail()` を付けます。不具合が直ると予期しない成功として失敗するため、その時点で指定を外します。Issue #470 で空状態の問題を修正して以降、該当するテストはありません。
