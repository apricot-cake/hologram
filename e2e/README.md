# e2e — Electron 画面 E2E とビジュアルリグレッション

実際の Electron を起動し、**実ポインタ・実キー入力**で画面を操作して確かめる層。他のテスト層との役割分担は `docs/testing.md` にある。ここはこの層固有の事情だけを書く。

```bash
npm run test:e2e         # 全部（フロー＋スクリーンショット）
npm run test:e2e:flow    # フローだけ（CI が回すのはこれ）
npm run test:e2e:update  # 正解画像を撮り直す
```

**先に `npm run build --workspace=app` が要る。** ビルド成果物が無いと起動を拒否される（`scripts/lib-electron-path.cts`）。

## 2つのプロジェクト

| プロジェクト | 置き場 | CI |
| --- | --- | --- |
| `flow` | `e2e/flows/` | `app-tests.yml`（1日1回・手動起動） |
| `visual` | `e2e/visual/` | **回さない** |

## 正解画像はローカル基準（#14・2026-07-29 決定）

正解画像はこの開発機で撮って repo にコミットし、**CI では照合しない**。業界標準は CI 基準（ランナー上で撮る）だが、その前提が本プロジェクトに無い。

- 標準が CI 基準を推す理由は「開発者ごとの機械差」と「開発機と CI の OS 差」で、単機・単独開発・両方 Windows の本プロジェクトはどちらにも当たらない
- 定番の解（Playwright 公式 Docker イメージの中で撮る・走らせる）は Ubuntu 系しか無く、Windows デスクトップアプリには使えない
- 同じ Windows でも、フォント・GPU の有無（ランナーは GPU 非搭載でソフトウェア描画）・表示設定が違えばピクセルは一致しない。しかも Playwright の接尾辞は両方 `win32` になり、同じファイル名を奪い合う
- 決め手は「**手元で照合できなくなること**」。見た目の退行に最初に気付くべき場所は UI を編集している最中＝手元で、そこを潰す代償のほうが大きい

再検討のトリガーは Issue #14 の同コメントにある。

## 撮る面を絞っている理由

全面再設計（#154）が進行中で、シェル（ツールバー・チップ帯・サイドバー）はまだ動く。初回に撮るのは**パネル・ダイアログ層**（インスペクタ／設定ダイアログ／確認ダイアログ）だけで、しかも**要素単位**で撮る＝ページ全体を撮ると背後のツールバーごと赤くなる。網羅化は #154 の収束後（#14・2026-07-25）。

## 決定性のために固定していること

`e2e/lib/harness.ts` が起動時に固定する。増やすときはここに足す。

- **ウィンドウの中身のサイズ** 1280×800（枠の寸法は OS 側の都合なので content で測る）
- **DPI** `--force-device-scale-factor=1`
- **テーマ** config.json に書いてから起動（`auto` を OS 設定で解決させない）
- **言語** `ja`／**タイムゾーン** `Asia/Tokyo`（どちらもラベル・日付を読むため）
- **フィクスチャ** 固定 ID・固定の絶対日時・固定の画像サイズと色（`e2e/lib/library.ts`）
- **アニメーション** `toHaveScreenshot` の `animations: 'disabled'`

しきい値は `maxDiffPixels: 0`。緩めるより、動く場所を `mask` で外すほうを先に試す。

## ユーザーの画面を奪わない

見えているウィンドウが要る層なので、**前面には出さない**。`HOLOGRAM_START_INACTIVE=1` でフォーカスを取らずに z 順の最背面へ送り、入力は CDP 経由で送る（フォーカス不要）。背面に送ると Chromium が描画を止めにかかるため、Playwright 自身がブラウザに渡すのと同じ抑止スイッチを起動時に渡している。

## サンドボックス

1ケースにつき `mkdtemp` の設定ディレクトリ＋ライブラリを作り、終了時に消す。`HOLOGRAM_SANDBOX=1` でネイティブホスト登録もしないので、実ライブラリ（`~/.hologram`／`~/Hologram/library`）にも実 Chrome の登録にも触れない。

## いま赤いことが分かっているもの

`test.fail()` が付いているケースは**アプリ側のバグ**で、直ると「予期しない成功」として赤くなる＝そのとき注釈を外す。現在は空状態の #470。
