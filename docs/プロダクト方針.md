# Hologram のプロダクト方針

Hologram は、イラストを中心に画像や動画を集め、出自や反応とともに保存して後から探せる個人用メディアライブラリです。この文書は、機能を追加するときに「何をどこまで保存・表示するか」を判断するための基準を示します。実装の構成は [アーキテクチャ.md](アーキテクチャ.md) を参照してください。

## 基本方針

- ライブラリに入れるものは、利用者が保存を選んだ画像、動画、または対応サイトの投稿です。
- 投稿には、取得できる範囲で投稿者、本文、日時、反応などのメタデータを添えます。ローカルの画像と動画はタグやフォルダで整理できます。
- 画像と動画はアプリ内で閲覧します。画像・動画以外のローカルファイルや、URLだけのページは新規に取り込みません。
- 保存するのはコンテンツとそのメタデータです。投稿ページの表示をそのまま画像として保存することは目的に含めません。

## 取り込み方

コンテンツの性質と保存の目的に応じて、取り込み方を 3 つに分けます。

| 対象 | 保存するもの | ねらい |
| --- | --- | --- |
| 流れていくプラットフォーム上の投稿 | 投稿本文、メタデータ、添付メディアなど | 削除や表示変更の前に、利用者が選んだ投稿を残します。 |
| ローカルの画像・動画 | ファイル本体 | 利用者の手元にある媒体を整理します。 |
| 対応サイト外の Web ページにある画像・動画 | 選んだ媒体、取得日時、出典ページ URL、取得できた汎用情報 | 投稿構造を推測せず、媒体を一般ウェブ由来として保存します。 |

対応サイト外では、利用者が選んだ画像や動画だけを保存します。ページ自体をブックマークとして保存せず、投稿構造、投稿者、反応数などのサイト固有情報を推測しません。

## 取得と表示を分けて考える

保存処理では、現在の表示や検索に使う正規化済みデータを残します。将来の再解析だけを目的に、第三者情報を含み得るプラットフォーム応答全体は保存しません。

一方、追加のリクエストが必要な情報は、通信量、利用者への影響、実際の用途を確認してから取り込みます。返信、スレッド、プロフィールの追加取得はこの扱いです。

画面表示、検索、並び替えは保存済みのデータから後で改善できます。実装するかどうかは利用者の課題と効果で判断します。

## 対象外

次の機能は、現在の製品の中心には置きません。

- 記事や小説を読むためのリーダー機能と本文抽出
- 汎用的なデジタル資産管理を主目的にした大規模なファイル管理
- 購読や巡回による自動収集
- 投稿ページのレイアウトやフォントまで含めた完全な画面アーカイブ
- アカウント認証を利用の前提にして、クラウドストレージをライブラリの正本とする構成（[#1120](https://github.com/apricot-cake/hologram/issues/1120)）
- ブラウザ拡張のタブをライブラリ本体とし、デスクトップアプリを置き換える構成（[#1120](https://github.com/apricot-cake/hologram/issues/1120)）

これらは恒久的に不可能とするものではありません。追加を検討するときは、この文書の基本方針と取り込み方に照らして、利用者が得る価値と保存の範囲を確認してください。
