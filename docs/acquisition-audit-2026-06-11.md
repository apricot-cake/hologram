# 拡張機能・取得パイプライン監査（2026-06-11）

多エージェント監査（45エージェント／6方向の調査→全37所見を敵対検証→28件確認・9件棄却）＋
実API照合テストの結果。対象は「クリック/ドラッグした投稿 → パーマリンク特定 → メタ取得 →
レコード化」の取得パイプライン（content.js / metadata.js / background.js / drag.js）。

## 総評

- **メタ取得層（metadata.js）は健全**: 正しいパーマリンクが渡れば、X/Bluesky/Misskey/Mastodon の
  実APIに対して作者・本文・日付・メディアを正しく解決する（実投稿照合 4/4 PASS。pixiv は照合
  スクリプト未対応）。
- **主要文脈のクリック保存はおおむね機能する**が、**リプライ・引用・詳細ページ・ドラッグ保存**に
  「別の投稿として保存される」系の実バグが複数ある（HIGH 5件）。ユーザーが info+ で目撃した
  「画像と作者が別人」クラスの問題は、**本拡張でも条件次第で起こる**。
- **手動テストの実績は約40セル中3セルのみ**（X TL / X 詳細 / Bluesky 詳細）。Misskey・Mastodon・
  pixiv・全ドラッグ保存・検索/プロフィール/引用/複数画像/動画は一度もテストされていない。

## 確認済みの問題（敵対検証を通過した28件）

### HIGH — 別投稿への誤帰属（画像とメタが食い違うレコードができる）

1. **[X/drag] フォトライトボックス中のドラッグは全画像がライトボックスの投稿に帰属**
   `drag.js:137-144` — URLバーの `/status/<id>/photo/N` が最優先で、ドラッグした画像自身の
   `/status/` アンカーを見ない（`!viewer` で短絡）。返信欄・おすすめ欄の画像をドラッグすると
   「投稿Aのurl/作者/本文 ＋ 投稿Bの画像」のレコードが緑バナー（完全成功）で保存される。
2. **[X/drag] 引用ツイートの画像ドラッグは引用した側（外側）に帰属**
   `drag.js:138,193-209` — 引用埋め込みは `div[role=link]` でアンカーが無く、祖先走査が外側
   記事のアンカーに到達。引用元Bの画像がAのレコードとして保存される（quotedUrl だけがBを指す）。
3. **[drag全般] 祖先走査に投稿境界が無く、アバター/バナー/サイドバー画像が「DOM上最寄りの投稿」に帰属**
   `drag.js:193-221` — body まで歩いて treeDistance 最寄りのアンカーを返すため、無関係な投稿の
   メタ＋アバター画像の捏造レコードが完全成功表示で保存される。pixiv ではさらに「隣の関連作品」に
   解決→その作品の p0 原画が保存され、画像もメタも触っていない投稿のものになる。
4. **[Bluesky] スレッド表示で引用ポストをクリックすると“引用された側”が保存される**
   `content.js:320-322,545-558` — スレッドのアンカー投稿は自分へのパーマリンクアンカーを持たず
   （日付はプレーンテキスト）、引用埋め込みだけが実 `<a>`。`links.find(handle一致) || links[0]`
   が引用元のURLを返し、url/作者/本文/メディア全部が引用元になる（スクショは引用した側）。
   本文中の bsky.app リンクや自己引用でも同型の誤りが起きる。
5. **[Misskey] リプライをキャプチャすると親ノートとして保存される**
   `content.js:638-677,590-608` — time付きリンクの document 順走査が、リプライ上部の親プレビュー
   （MkNoteSub）のリンクを先に拾う。url/作者/本文/メディア全部が親ノートになる。
   詳細ページでは conversation（先祖チェーン）が先に並ぶため最上位先祖のIDが選ばれる。

### MEDIUM

6. **[Misskey] ノート詳細で下部の返信/上部の先祖をクリックするとメインノートが保存される**
   `content.js:590-608` — MkNoteSub に tabindex が無く、探索が詳細ルートまで上がる。クリックした
   返信はスクショにも入らない。
7. **[X] record.url が非パーマリンク（`/photo/1`・`/analytics`・ライトボックスURL）になる経路**
   `content.js:283,499-533` — time付きアンカーが無い詳細ページ本体ツイートで `links[0]` 採用＋
   `parseXPostLink` が href をそのまま返す。メタは正しいがURL契約違反（開くとライトボックスが開く等）。
8. **[Bluesky/drag] 詳細ページのドラッグ保存で url が `/liked-by` `/reposted-by` 付きになる**
   `drag.js:159-163` — 正規表現が末尾アンカー無し＋エンゲージ数リンクを拾う。メタは正しい。
9. **[X] media[] が `?name=orig` 無しで保存され、原寸ではなく中サイズがDLされる**
   `metadata.js:77-87` — 実測で bare URL = medium と同一バイト。しかもドラッグの「成功」経路ほど
   低解像度になる逆転（マッチ時は bare、失敗時のみ hiRes）。サイドカーの width/height とも不一致。
10. **[pixiv] 複数ページ作品の media[] が p0 の拡張子を全ページに流用** `metadata.js:387-403` —
    jpg/png混在作品で 404。クリック保存はページ黙殺・ドラッグ保存は**保存自体が失敗**する。
    `/ajax/illust/<id>/pages` を引くべき。
11. **[pixiv/drag] `_pN` の無い画像をドラッグすると黙って media[0]（p0）が保存される**
    `background.js:260-267` — imageIndex=null のまま p0 を断定保存。X/Bluesky の挙動（ドラッグ画像
    維持）とも非対称。
12. **[pipeline] captureVisibleTab は「アクティブタブ」を撮る** `background.js:76` — クリック直後の
    タブ切替で、別ページのスクショが正しいメタと結合され得る（撮影可能なタブに限る・要 active 検証）。
13. **[pipeline] クロップ矩形がクリック時点で固定** `content.js:133-146,216-228` — 慣性スクロール・
    遅延画像ロードのレイアウトシフトで、隣の投稿が写った画像＋クリック投稿のメタになる。
14. **[pipeline] ビューポートより背の高い投稿は下部が黒帯** `content.js:126-130,217-227` — canvas
    が rect 全高・撮影はビューポートのみ。長文ノートの後半が黒で保存される。
15. **[pipeline] メタ取得失敗時に record.date がキャプチャ時刻にフォールバック** `background.js:102,228`
    — 「投稿日」として保存され、ビューアの日付フィルタ/ソートを汚す。null 維持かフラグが必要。

## 監査の射程外（completeness critic の指摘・未調査）

1. 本文中に貼られた /status/ 等のURLがパーマリンクとして拾われる経路（X詳細の links[0] 等と同根）
2. ドラッグが投稿外画像（アバター/バナー/カードサムネ/動画ポスター）を受理する問題の全域
3. ブースト/リノートのラッパー未展開（リンクがラッパーに解決した場合、作者がブースト側になる）
4. CW/NSFW 状態がレコードに残らない（spoiler_text/cw/sensitive 喪失・ビューアで再ゲート不可）
5. Bluesky 引用埋め込みクリック→location.href フォールバックの誤帰属（スレッドページ）
6. X syndication の長文切り詰め・年齢制限ツイートの tombstone（本文がスクショと食い違う）
7. 仮想リストのDOMリサイクル（クリック→撮影間で隣の投稿が rect に入る）
8. 編集/削除との時間差（スクショ後にAPIを引くため、編集後の本文が編集前の画像に付く）

## 修正の推奨順序

1. **drag.js の帰属境界**（#1,2,3,11）: 祖先走査を「ドラッグ画像を内包する投稿コンテナ」に限定し、
   ライトボックス優先は本体画像のみに。マッチ失敗時に画像を差し替えない。
2. **クリック側のパーマリンク選定**（#4,5,6,7,8）: 走査スコープを「クリックした投稿の article」内に
   限定し、引用埋め込み・親プレビューのリンクを除外。X/Bluesky/Misskey 共通の構造問題。
3. **画質・URL正規化**（#9,10）: X `?name=orig` 付与、pixiv `/ajax/illust/<id>/pages` 使用、
   パーマリンクの canonical 再構築（/photo/N 等の接尾辞除去）。
4. **撮影の整合**（#12,13,14）: active タブ検証・撮影直前の rect 再計測・ビューポート高クランプ
   （または分割撮影）。
5. **フラグ系 LOW**（#15,16,19,20,22,23,25 など）はまとめて小修正。
