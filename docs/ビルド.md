# 開発、ビルド、配布

この文書では、開発環境の準備、アプリと拡張機能の起動、検証用の隔離環境、配布物の作成を説明します。初めて作業する場合は、ここから始めてください。

## 必要な環境

- Node.js 22.18 以上
- Windows でデスクトップアプリを動かせる環境
- Chrome 拡張機能を確認する場合は Chrome

依存関係は、リポジトリ直下で次のコマンドを実行して準備します。

```powershell
npm run setup
```

このコマンドは、ルートと `extension/` の依存関係を準備し、拡張機能をビルドします。通常の `npm install` では必要な回避策が適用されないため、依存関係の準備には `npm run setup` を使用してください。

アプリを起動中に依存関係を更新しないでください。実行中のプロセスがネイティブモジュールを使用していると、更新に失敗したり、依存関係が不完全な状態になったりします。

新しい worktree でも、最初に `npm run setup` を実行してください。ほかの worktree の `node_modules` を共有しないでください。

## アプリを起動する

通常の開発では、次のコマンドで Electron アプリを起動します。

```powershell
$env:REMOTE_DEBUGGING_PORT = "9222"
npm run dev --workspace=app
```

renderer の多くの変更はそのまま反映されます。main、preload、ネイティブホスト、起動設定を変更した場合は、アプリを再起動して確認してください。

実際のライブラリを使って利用者に確認を依頼する場合は、次を実行します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\restart-app.ps1
```

自分で機能を試すときは、実データではなく隔離したサンドボックスを使います。

```powershell
node scripts/sandbox-app.cts
```

実データでしか再現しない表示や性能の問題は、実ライブラリを直接開かず、読み取り用のコピーを作る `--real` を使います。

```powershell
node scripts/sandbox-app.cts start --real
```

停止するときは、同じ worktree で次を実行します。

```powershell
node scripts/sandbox-app.cts stop
```

## 拡張機能を開発する

拡張機能は、日常用のブラウザプロファイルとは別の開発用プロファイルで確認します。

1. 次を実行したままにして、開発ビルドを監視します。

   ```powershell
   npm run dev:ext
   ```

2. 別のターミナルで、開発用プロファイルを開きます。

   ```powershell
   npm run ext:dev:browser
   ```

3. 初回だけ、開いたブラウザで拡張機能の管理画面を開き、開発ビルドの出力フォルダを unpacked 拡張機能として読み込みます。以後は同じプロファイルを使います。

開発用プロファイルには、必要なテスト用アカウントだけでログインしてください。日常のプロファイルには開発ビルドを読み込まないでください。

リリース用の拡張機能を作るには、次を実行します。

```powershell
npm run build:ext
```

日常用の出力へ反映する操作は、確認済みのビルドに限って行います。

```powershell
npm run deploy:ext
```

## 検証する

変更後は、少なくとも次を実行します。

```powershell
npm run check
```

変更が保存、IPC、ネイティブホスト、アプリ起動に関係する場合は、さらに次を実行します。

```powershell
node scripts/run-app-tests.cts
```

実際のポインタ操作やスクリーンショットに影響する変更は、次も実行します。

```powershell
npm run test:e2e
```

どのテストを選ぶかは [テスト.md](テスト.md) を参照してください。

## 保存に失敗したとき

まず、拡張機能とアプリが同じ開発環境を使っていることを確認します。次に、設定ディレクトリ内のログを確認してください。Windows の既定の場所は `%APPDATA%\Hologram` です。

確認する順番は次のとおりです。

1. 拡張機能の診断ページで、ホストへ接続できているかを確認します。
2. アプリのログで、取込キューと SQLite への取り込みに失敗していないかを確認します。
3. ホストのログで、保存先フォルダ、メディアのダウンロード、メッセージ形式のエラーを確認します。

不具合を報告するときは、再現手順、保存しようとしたサイト、表示されたメッセージ、該当するログの時刻を添えてください。個人情報や認証情報は共有しないでください。

## 配布物を作る

デスクトップアプリの配布物は、次のコマンドで作成します。

```powershell
npm run dist --workspace=app
```

出力先は `app/dist/` です。配布前に、クリーンな環境でアプリを起動し、拡張機能との保存、ライブラリの作成、既存ライブラリの読み込みを確認してください。

## アイコンを更新する

元画像 `assets/icon-master.png` を差し替えた後、リポジトリ直下で次を実行します。

```powershell
node_modules/.bin/electron scripts/make-icons.cjs
```

正方形で 512 px 以上の元画像を使ってください。
