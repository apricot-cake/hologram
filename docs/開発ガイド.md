# 開発ガイド

この文書は、開発環境の準備、アプリと拡張機能の起動、検証、配布物の作成を扱います。コードの構成を先に知りたい場合は [アーキテクチャ.md](アーキテクチャ.md) を参照してください。

## 準備

Windows でデスクトップアプリを動かせる環境と、Node.js 22.18.0 が必要です。拡張機能を確認する場合は Chrome も用意してください。対応するバージョン管理ツールでは、リポジトリ直下の `.node-version` を読みます。手動で設定する場合も `22.18.0` を使ってください。`package.json` の `engines` は依存利用者向けの互換性下限です。

コミット前にステージ済みの秘密情報を検査する場合は、[Gitleaks の公式リリース](https://github.com/gitleaks/gitleaks/releases) から対応する OS のバイナリを導入し、`gitleaks` を `PATH` に追加してください。未導入の環境ではローカル検査を警告付きでスキップしますが、GitHub Actions の検査は必ず実行します。`.gitleaksignore` は導入時に確認した既存履歴の誤検出だけを fingerprint で除外しています。新しい検出をパターン単位で除外しないでください。

リポジトリのルートで、次を一度実行します。

```powershell
npm run setup
```

このコマンドはルートと `extension/` の依存関係を準備し、拡張機能をビルドし、共有のコミット前フックを有効にします。必要な回避策を含むため、依存関係の準備には `npm install` ではなく `npm run setup` を使います。

アプリを起動したまま依存関係を更新しないでください。ネイティブモジュールを使用中だと更新に失敗したり、依存関係が不完全になったりします。新しい worktree では依存関係を共有せず、その worktree で `npm run setup` を実行してください。

## デスクトップアプリを起動する

### 隔離した環境で確認する

自分で変更を確かめるときは、既定でサンドボックスを使います。フィクスチャのライブラリと設定ディレクトリで HMR 開発版を起動するため、実ライブラリには触れません。

```powershell
node scripts/sandbox-app.cts
```

停止するときは、同じ worktree で次を実行します。

```powershell
node scripts/sandbox-app.cts stop
```

フィクスチャでは再現しない表示や性能の問題だけは、実ライブラリの読み取り用コピーで確認できます。

```powershell
node scripts/sandbox-app.cts start --real
```

このモードで起動したウィンドウには実データが含まれます。スクリーンショットを Issue やプルリクエストへ貼らないでください。

### 実ライブラリで利用者に確認を依頼する

画面や実際の挙動を利用者に確認してもらうときだけ、次を実行します。隔離用の環境変数を外し、実ライブラリを表示する HMR 開発版を起動します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\restart-app.ps1
```

確認してほしい操作と期待結果を添えて依頼してください。

## 拡張機能を開発する

日常用とは別の開発用ブラウザプロファイルで確認します。

1. 開発ビルドを監視します。

   ```powershell
   npm run dev:ext
   ```

2. 別のターミナルで開発用プロファイルを開きます。

   ```powershell
   npm run ext:dev:browser
   ```

3. 初回だけ、ブラウザの拡張機能管理画面で開発ビルドの出力フォルダを unpacked 拡張機能として読み込みます。

このコマンドは開発用プロファイルだけで CDP を `http://127.0.0.1:9223` に公開します。接続状態とプロファイルのパスは次で確認できます。

```powershell
npm run ext:dev:cdp
```

CDP が未接続と表示された場合は、開発用プロファイルのウィンドウをすべて閉じてから `npm run ext:dev:browser` を実行します。日常用プロファイルには CDP を公開しません。

開発用プロファイルには必要なテスト用アカウントだけでログインしてください。日常用プロファイルに開発ビルドを読み込まないでください。

リリース用の拡張機能は次で作成します。

```powershell
npm run build:ext
```

日常用の出力へ反映する操作は、確認済みのビルドに限ります。

```powershell
npm run deploy:ext
```

## 検証する

変更後は、まず次を実行します。

```powershell
npm run check
```

保存、IPC、Native Messaging、アプリの起動に関わる変更では、さらに次を実行します。

```powershell
node scripts/run-app-tests.cts
```

ポインタ操作やスクリーンショットに影響する変更では、アプリをビルドして画面 E2E も実行します。

```powershell
npm run build --workspace=app
npm run test:e2e
```

テストの選び方、拡張機能の E2E、基準画像の更新は [テスト.md](テスト.md) を参照してください。

## 配布物を作る

デスクトップアプリの配布物は次で作成します。

```powershell
npm run dist --workspace=app
```

出力先は `app/dist/` です。配布前にクリーンな環境でアプリを起動し、拡張機能との保存、ライブラリの作成、既存ライブラリの読み込みを確認してください。

## 保存に失敗したとき

拡張機能とアプリが同じ開発環境を使っていることを確認してから、設定ディレクトリ内のログを確認します。Windows の既定の場所は `%APPDATA%\Hologram` です。

1. 拡張機能の診断ページでホストへ接続できているかを確認します。
2. アプリのログで取込キューと SQLite への取り込みに失敗していないかを確認します。
3. ホストのログで保存先フォルダ、メディアのダウンロード、メッセージ形式のエラーを確認します。

不具合を報告するときは、再現手順、保存しようとしたサイト、表示されたメッセージ、該当するログの時刻を添えてください。個人情報や認証情報は共有しないでください。

## アイコンを更新する

元画像 `assets/icon-master.png` を差し替えた後、リポジトリのルートで次を実行します。

```powershell
node_modules/.bin/electron scripts/make-icons.cjs
```

正方形で 512 px 以上の元画像を使ってください。
