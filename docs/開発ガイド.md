# 開発ガイド

この文書は、開発環境の準備、アプリと拡張機能の起動、検証、配布物の作成を扱います。コードの構成を先に知りたい場合は [アーキテクチャ.md](アーキテクチャ.md)、表示言語を追加する場合は [ローカライズ.md](ローカライズ.md) を参照してください。

## 準備

Windows でデスクトップアプリを動かせる環境と、Node.js 22.18.0 が必要です。拡張機能を確認する場合は Chrome も用意してください。対応するバージョン管理ツールでは、リポジトリ直下の `.node-version` を読みます。手動で設定する場合も `22.18.0` を使ってください。`package.json` の `engines` は依存利用者向けの互換性下限です。

シークレットは GitHub Actions で検査します。Gitleaks は CI 内でのみ実行し、開発 PC には導入しません。`.gitleaksignore` は導入時に確認した既存履歴の誤検出だけを `fingerprint` で除外しています。新しい検出をパターン単位で除外しないでください。

リポジトリのルートで、次を一度実行します。

```powershell
npm run setup
```

このコマンドはルートと `extension/` の依存関係を準備し、共有のコミット前フックを有効にします。必要な回避策を含むため、依存関係の準備には `npm install` ではなく `npm run setup` を使います。

アプリを起動したまま依存関係を更新しないでください。ネイティブモジュールを使用中だと更新に失敗したり、依存関係が不完全になったりします。新しいワークツリーでは依存関係を共有せず、そのワークツリーで `npm run setup` を実行してください。

## デスクトップアプリを起動する

### ショートカットから使うアプリへ反映する

```powershell
npm run deploy:app
```

別ディレクトリでビルドし、成功した出力を `app/out` へ配備してから更新を通知します。起動中のアプリはファイル変更イベントで通知を受け取り、取り込み・書き出し・DB バックアップなどの処理が終わると自動で再起動します。ビルドに失敗した場合は、配備も通知も行いません。アプリを閉じている場合は、次のショートカット起動から新しい出力を使います。

この方式は、チェックアウトのビルド済みアプリを直接起動する場合に使います。開発サーバー、ショートカットの変更、定期ポーリングは不要です。通知を受け取る機能が入っていない旧版から切り替える最初の一回だけ、通常の再起動が必要です。インストール版と HMR 開発版は対象外です。`npm run build --workspace app` はビルドのみで、更新を通知しません。

自己再起動には Electron の [app.relaunch](https://www.electronjs.org/docs/latest/api/app#apprelaunchoptions) と通常の終了処理を使います。拡張機能の配備は引き続き `npm run deploy:ext` で行います。

### 隔離した環境で確認する

自分で変更を確かめるときは、既定でサンドボックスを使います。フィクスチャのライブラリと設定ディレクトリで HMR 開発版を起動するため、実ライブラリには触れません。

```powershell
node scripts/sandbox-app.cts
```

停止するときは、同じワークツリーで次を実行します。

```powershell
node scripts/sandbox-app.cts stop
```

フィクスチャでは再現しない表示や性能の問題だけは、実ライブラリの読み取り用コピーで確認できます。

```powershell
node scripts/sandbox-app.cts start --real
```

このモードで起動したウィンドウには実データが含まれます。スクリーンショットを Issue やプルリクエストへ貼らないでください。

## 拡張機能を開発する

開発用と日常用の Chrome プロファイルは、同じリリースビルド `extension/.output/chrome-mv3/` を読みます。HMR と開発専用バンドルは使いません。違いはネイティブメッセージングホストだけです。日常用は実ライブラリにつながる `com.hologram.host`、開発用は隔離した `~/.hologram-dev` につながる `com.hologram.host.dev` を使います。

初回だけ、開発用ネイティブメッセージングホストを登録します。

```powershell
npm run ext:dev:register
```

このコマンドは HKCU と `~\.hologram-dev` へ書き込みます。Chrome と同じ Windows ユーザー領域から実行してください。ユーザー領域から隔離された実行では、登録前に失敗します。

拡張機能を変更したら、共有リリースビルドを配備します。

```powershell
npm run deploy:ext
```

このコマンドはリリースビルドを 1 回だけ生成して検証します。開発用 Chrome が起動中なら、[CDP の Extensions API](https://chromedevtools.github.io/devtools-protocol/tot/Extensions/) で同じ展開済み拡張機能を読み込み直します。日常用 Chrome にはネイティブメッセージングホストを通して新しいビルドを知らせ、保存や一括取り込みを中断しない時点で拡張機能自身が [`chrome.runtime.reload()`](https://developer.chrome.com/docs/extensions/reference/api/runtime#method-reload) を実行します。

開発用 Chrome では、その後に常駐コンテンツスクリプトの対象サイトのタブを [CDP の Page.reload](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-reload) で再読み込みします。対象は配備した manifest から取得し、読み込み完了まで待ちます。対象外のサイトと日常用 Chrome のタブは再読み込みしません。サイトの読み込みに失敗した場合はコマンドも失敗として終了します。

日常用 Chrome への通知は `%APPDATA%\Hologram\extension-build.json` へ書きます。ユーザー領域から隔離された実行では、ビルド前に失敗します。

開発用プロファイルを開きます。

```powershell
npm run ext:dev:browser
```

このコマンドは開発用プロファイルだけで CDP を `http://127.0.0.1:9223` に公開し、共有ビルドを読み込みます。さらに、このプロファイルの [`chrome.storage.local`](https://developer.chrome.com/docs/extensions/reference/api/storage#storage_areas) に開発用ネイティブメッセージングホストの設定を書きます。拡張機能管理画面で手動読み込みする必要はありません。接続状態とプロファイルのパスは次で確認できます。

```powershell
npm run ext:dev:cdp
```

CDP が未接続と表示された場合は、開発用プロファイルのウィンドウをすべて閉じてから `npm run ext:dev:browser` を実行します。以後は開発用 Chrome を起動したまま `npm run deploy:ext` を繰り返します。

開発用 Chrome は、背面や他のウィンドウに隠れた状態でも検証対象の描画とタイマーを維持します。画面の表示状態によって実機検証の結果が変わらないようにするためです。

開発用プロファイルには必要なテスト用アカウントだけでログインしてください。

## 検証する

通常の変更後は、次を実行します。

```powershell
npm run check
```

拡張機能のソース、マニフェスト、またはバンドル方法を変更した場合は、代わりに次を実行します。このコマンドは通常の検証に加え、テスト専用の Chrome バンドルを使う検査を実行します。

```powershell
npm run check:extension
```

保存、IPC、ネイティブメッセージング、アプリの起動に関わる変更では、さらに次を実行します。

```powershell
node scripts/run-app-tests.cts
```

ポインタ操作やスクリーンショットに影響する変更では、アプリをビルドして画面 E2E も実行します。

```powershell
npm run build --workspace=app
npm run test:e2e
```

テストの選び方、拡張機能の E2E、基準画像の更新は [テスト.md](テスト.md) を参照してください。

## 配布物を作る

### 拡張機能

Chrome ウェブストアへ提出するときは、Chrome 用のリリース成果物を作成して検証します。

```powershell
npm run check:release
```

出力先は `extension/.output/chrome-mv3-release/` です。`check:release` は内部で `npm run build:ext` を実行します。通常の変更検証には「検証する」のコマンドを使います。

### デスクトップアプリ

デスクトップアプリの配布物は次で作成します。

```powershell
npm run dist --workspace=app
```

出力先は `app/dist/` です。Windows向けのNSISパッケージだけを作ります。配布前にクリーンなWindows環境でアプリを起動し、拡張機能との保存、ライブラリの作成、既存ライブラリの読み込みを確認してください。

## 保存に失敗したとき

拡張機能とアプリが同じ開発環境を使っていることを確認してから、`%APPDATA%\Hologram` 内のログを確認します。

1. 拡張機能の診断ページでホストへ接続できているかを確認します。
2. アプリのログで取り込みキューと SQLite への取り込みに失敗していないかを確認します。
3. ホストのログで保存先フォルダ、メディアのダウンロード、メッセージ形式のエラーを確認します。

個人情報や認証情報は共有しないでください。

## アイコンを更新する

元画像 `assets/icon-master.png` を差し替えた後、リポジトリのルートで次を実行します。

```powershell
node_modules/.bin/electron scripts/make-icons.cjs
```

正方形で 512 px 以上の元画像を使ってください。
