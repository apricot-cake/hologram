# テスト

テストは、速く確認できる単体・統合テストから、実際のアプリとブラウザを動かすテストまで段階的に用意しています。変更に近い層から実行し、保存経路や画面操作に関わる変更では上位の層も実行してください。

## まず実行するコマンド

| 目的 | コマンド |
| --- | --- |
| 静的解析、型検査、単体・統合テスト | `npm run check` |
| 単体・統合テストのみ | `npm test` |
| 拡張機能のソースと Chrome テスト用バンドル | `npm run check:extension` |
| Chrome・Firefox のリリース成果物 | `npm run check:release` |
| 型検査のみ | `npm run typecheck` |
| アプリ、ネイティブホスト、拡張機能の結合テスト | `node scripts/run-app-tests.cts` |
| 実ポインタ・実キー操作による画面 E2E | `npm run test:e2e` |
| 通常の画面フロー E2E のみ | `npm run test:e2e:flow` |
| ビジュアル基準画像を更新する | `npm run test:e2e:update` |
| 拡張機能のオフライン E2E | `npm run test:e2e-extension` |

依存関係がない worktree では、先に `npm run setup` を実行してください。

## テストの使い分け

### `npm test`

Vitest による単体・統合テストです。純粋な変換、データベースの振る舞い、IPC の契約、renderer の状態管理などを確認します。ビルド済み拡張機能を直接読むテストは含みません。ロジックを変更した場合は必ず実行してください。

### `npm run check:extension`

通常の検証に加え、`extension/.output/chrome-mv3-test/` に Chrome のテスト専用バンドルを作り、生成された manifest、注入用スクリプト、ページ内 UI を検査します。拡張機能のソース、マニフェスト、またはバンドル方法を変更した場合に実行してください。ストア提出用と日常用プロファイルの出力は変更しません。

### `node scripts/run-app-tests.cts`

Electron アプリ、Native Messaging ホスト、拡張機能の境界を通すテストを実行します。各テストは一時ディレクトリと専用の設定を使うため、通常は実ライブラリや起動中のアプリに影響しません。

一部だけ実行する場合は、テスト名の一部を指定できます。

```powershell
node scripts/run-app-tests.cts tabs extension-orphan
```

並列実行で不安定になる場合だけ、次のように並列数を下げます。

```powershell
$env:APP_TESTS_JOBS = "1"
node scripts/run-app-tests.cts
```

### `npm run test:e2e`

Playwright による画面 E2E とビジュアルテストです。実際のポインタとキー入力で、クリックできない要素、重なり、レイアウト、キーボード操作を確認します。起動前にアプリをビルドする必要があります。

```powershell
npm run build --workspace=app
npm run test:e2e
```

基準画像の更新は意図した見た目の変更を確認してから行ってください。環境による差を直す目的で無条件に更新しません。詳細は `e2e/README.md` を参照してください。

### 拡張機能の E2E

`test:e2e-extension` などの `test:e2e-*` スクリプトは、使い捨ての Chromium と Chrome のテスト専用バンドルを使います。保存のタイムアウト、重複保存、ページ上の UI、拡張機能の更新後の状態を確認するときに実行してください。

スクリプトの一覧と実行内容は、リポジトリ直下の `package.json` を参照してください。

## 新しいテストを追加する

- 純粋なロジックは Vitest のテストとして追加します。
- main、preload、renderer、Native Messaging の連携は `scripts/test-app-*.cts` として追加します。
- 実際の画面操作や視覚的な結果は `e2e/flows/` または `e2e/visual/` に追加します。
- 拡張機能のブラウザ上の挙動は `scripts/e2e-extension-*.cts` に追加します。

テストは、実データ、固定ポート、共有の設定ディレクトリ、日常用のブラウザプロファイルに依存しないようにしてください。必要な状態は各テストで作成し、終了時に片付けます。

## 手動で投稿を確認する

自動テストで確認できない投稿は、隔離した開発用プロファイルとサンドボックスライブラリを使って確認してください。手順は [開発ガイド.md](開発ガイド.md) の「拡張機能を開発する」と「デスクトップアプリを起動する」を参照してください。

実サービス上の投稿を試す場合は、公開範囲、ログイン状態、投稿内容が結果に影響することを記録してください。個人情報や認証情報をテストデータ、ログ、スクリーンショットに残さないでください。
