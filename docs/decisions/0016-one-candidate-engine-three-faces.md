# 0016. 「タイプ→候補」のエンジンは1つ・面は3つにする

- 状態: 採用（2026-07-11 決定・2026-07-30 実装）
- 関連: #28・#148・#29・[0002](0002-dependency-adoption-criteria.md)・[0008](0008-single-smart-search.md)

## 背景

「文字を打って候補から選ぶ」面が増えていく見通しがあった。検索ボックス直下のサジェスト（実装済み）、コマンドパレット（#28）、クエリチップ帯のインライン入力（#148）で、どれも「タグ・投稿者・フォルダを名前で引き当てる」ところは同じ。

面ごとに候補生成を書くと、同じ文字を打っても面によって出る顔ぶれ・並び・種別ラベルが違う、という形で必ず食い違う。しかも食い違いは静かに起きる（どの面も単体では正しく見える）。

## 決定

**候補の供給源を1つのレジストリに集約し、面はそこから引くだけにする。**

- レジストリ（`services/command-registry.ts`）が持つのは、エントリの登録（固定リスト／`entries(query)` の provider）、絞り込みと並び、開閉状態。
- エントリは `{ id, section, title, keywords?, hint?, weight?, perform() }` の1種類だけ。フィルタ系（タグへジャンプ）も操作系（設定を開く）も `perform()` 1本に正規化し、**型を分けず差は section（見出し）だけ**にする。
- **並びは 完全一致 > 前方一致 > 部分一致 > あいまい**。あいまいの判定は既存 `search.ts` の `compile()` をそのまま使う（[0008](0008-single-smart-search.md) の単一マッチャー）。同じスコア帯では `weight`（タグの使用回数・投稿者の投稿数）、それも同じなら登録順。
- **面が決めるのは「どの section を何件見せるか」と「確定したときの既定動作」だけ**。面の統合はしない＝検索ボックスは現タブのライブ絞り込み、パレットはコマンド実行とジャンプ、#148 はチップ化のまま。
- **件数はパレットが上限なし・検索ボックスがタグ6件/投稿者4件**。上限なしはアプリ内の候補一覧の作法に合わせたもの（「+ フィルタ」バーの一覧は上限なしでスクロール、サイドバーのファセット行は100件）＝当たった分を全部出し、足りなければ打ち足すかスクロールする。検索ボックスだけ絞るのは、あちらが入力欄直下のドロップダウンで縦に伸ばせないため。実ライブラリ規模（約1万件）での最悪ケースは候補580件で、確定まで150〜190ms・スクロールは即時（2026-07-30 実測）。

## 影響

- 検索ボックスのサジェストを作っていた `buildSuggest`（`services/users.ts`）は廃止し、レジストリの corpus provider（`services/command-builder.ts`）へ合流。検索ボックスは `queryEntries(q, { sections: ['tag','user'], limit: { tag: 6, user: 4 } })` を読むだけになった。
- 確定動作も共有する＝タグ・投稿者のエントリの `perform()` は検索ボックスの `onPick`（`search-editing` の pick を履歴コアレスで包んだもの）を呼ぶ。パレットから選んでもサジェストから選んでも同じ「現在のタブに AND 追加」になる。
- ショートカットの役割分担を確定＝`/` は検索ボックスへのフォーカス、**Ctrl/Cmd+K はパレット**（以前は両方が検索ボックスへのフォーカスだった）。
- 器は shadcn Dialog（＝Base UI Dialog）＋ Base UI Autocomplete の `inline` モードで、追加依存はゼロ。scrim・フォーカストラップ・復帰・スクロールロック、ウィンドウ操作ボタンの減光（`.wc-dim`）まで既存の仕組みがそのまま効く。
- `perform()` は**閉じてから実行する**（`runEntry`）。順序を逆にすると、Dialog のフォーカス復帰先が perform 後の DOM になり、perform が別のモーダルを開く場合は閉じ処理と競合する。

## 却下した案

- **cmdk（shadcn の Command が使うライブラリ）**: Radix 依存で a11y スタックが二重化する。加えて内蔵スコアラを持つため、マッチの意味論が `search.ts` と二重規格になる——[0008](0008-single-smart-search.md) が1本に畳んだものをパレットだけ別基準に戻すことになる。**リポジトリに既に入っており（`components/ui/command.tsx` 経由でフィルタバーが使っている）「在るから使う」誘引が強いので、ここに明記して残す**（[0002](0002-dependency-adoption-criteria.md)＝依存ツリーに在ることは採用根拠ではない）。
- **自前オーバーレイ**: ヘッドレス部品へ寄せる方針の明文違反。
- **#29（全文検索）と器を2セット建てる**: オーバーレイ・入力・一覧・キーボードナビ・CSS を二重に持つことになる。VS Code が別器なのは常設サイドバーがあるため。単一ウィンドウのライブラリアプリ（Raycast / Linear / Slack / Notion）は合流側が標準。
- **Slack 式「検索ボックスがパレットの召喚器」**: 上の役割分担（`/` と Ctrl+K）と衝突する。
- **入口を右上の ⋮ メニューに置く**: #146 で却下済み（左ナビレールを持つアプリは全域の入口をサイドバー側に置く）。見える入口は**サイドバーのフッター項目**と**検索ボックス右端の Ctrl+K バッジ**の2つ。
