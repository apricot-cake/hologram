# 0027. 左サイドバーはレール1本にする（展開カラムを持たない）

- 状態: 採用（2026-08-06）
- 関連: #981／[ADR 0018](0018-labeled-navigation-rail-default.md) の「決定」3点目（展開⇄レールのトグルと永続化は現行維持）を**置き換える**（双方向リンク：0018 側に本 ADR への前方リンクを追記済み）／同 ADR のフッターのミラー状態表示に関する判断も置き換える（下記）／#149（開閉トグル）・#30 のサイドバー側（幅のドラッグ）・#259 のサイドバー側（幅連動の退避）を撤回／#245（一括畳み）は存置

## 背景

ADR 0018（#678）は既定をレールにしたが、展開カラムとそのトグル・永続化はそのまま残した。#965 がレールに「グループ1つにつき固定行1つ＋フライアウト」を置いたことで、展開カラムにしか無い機能は無くなった——フライアウトの中身は展開時と同じツリー／リストで、作成・改名・削除・並べ替えまで同じ。

残ったのは費用と事故だけだった。

1. **同じ中身を2通りに描いていた**。`LeftSidebar` はユーザー生成の3グループをカラム用とフライアウト用に二重レンダーし、どちらを見せるかを `group-data-[collapsible=icon]` の分岐で切り替えていた。
2. **見えない状態が最大化のときだけ現れた**。#259 は狭幅でレールへ退避させるが、その間のトグルは一時状態にしか書かれない（保存済み選好を幅で汚さないための設計）。常用ウィンドウが 1280px 未満だと保存値へ到達する手段が無く、#678 より前に書かれた `sidebarOpen: true` が最大化のときだけ蘇る。2026-08-06 に実機で発生した。
3. **ウィンドウ最小幅がモバイル分岐を踏めた**。shadcn Sidebar は `md`（768px）未満で Sheet に変わるが、ウィンドウの最小幅は 720px。720〜767px ではサイドバーが開く手段の無い Sheet になり、事実上消えていた。

## 決定

**左サイドバーの提示形はラベル付きレール（`--sidebar-width-icon` = 4.5rem）1つだけとする。展開カラムと、そこへ至る経路をコードから撤去する。**

- `SidebarProvider` は開閉状態を持たない＝`state` は定数 `'collapsed'`。`open` / `setOpen` / `toggleSidebar` と、それらを読む分岐は無い
- 開閉トグルを撤去＝`SidebarTrigger`（サイドバーのヘッダー行にあった）と Ctrl+B。ヘッダー行はタイトルバーのドラッグ帯として残す（#154 のシェル・#628 の軸は不変）
- 開閉の永続化を撤去＝`services/sidebar-pref.ts` と pref キー `sidebarOpen`
- 幅を撤去＝`sidebarWidth` と `SidebarRail`（#30 のサイドバー側）。レールは固定幅で、ドラッグする対象が無い。インスペクタ側のドラッグリサイズは存置
- 幅連動の退避を撤去（#259 のサイドバー側）。~~`services/layout-mode.ts` の `isWide()` は他に利用者が残るので存置~~ ← **誤り（#988 で訂正）**。残っていた利用者は `WIDE_MIN_PX`（E2E とハーネスの幅）だけで、`isWide()` / `subscribe()` の読み手は本 ADR で消えた AppShell の1つが最後だった。#975 と併せて幅で形を変える箇所はゼロになったので、ストア自体を撤去し `layout-mode.ts` はブレークポイントの定数だけを持つ
- モバイル Sheet 分岐を撤去（背景3）
- ユーザー生成の3グループはフライアウトのみ＝二重レンダーを1本化
- **ミラー状態表示（`BackupStatus`）はレールにアイコンで出す**。ADR 0018 はこれを「レール時は隠し展開時のみ」と決めていたが、展開が無くなると恒久的に不可視になり、DB 整合性・孤児の警告を出す唯一の面が消える。0018 がラベル無しアイコンを禁じたのは**行き先**（名前を字面から推測できず、押して移動するもの）についてであって、状態表示は押して行く先が無い＝別種。全文は `title` で読める
- **#245 の一括畳み（Ctrl+Shift+B）は存置**。これは提示形ではなく「周辺 UI をまとめて消す」機能で、消えた先は無表示。表示ポップオーバーの説明文からは Ctrl+B の半分を落とす

## 標準

- レールに展開形を持たせないのは定型：VS Code のアクティビティバーは入口のアイコン列だけを持ち、幅の変わる展開形が無い（ADR 0018 の調査どおり）。M3 でも Navigation rail と Navigation drawer は別部品で、rail 単体で完結する
- #243 が確立し #975 が戻した「提示形は幅で変えない」原則とは、形が1つになることで自動的に整合する
- 一方、**トグルを持つ実装も同じくらい標準的**（Obsidian / Lightroom / VS Code のサイドバー本体）。本 ADR はそちらを否定していない＝Hologram のサイドバーが**恒久的に薄い**（ADR 0018 の診断＝サイドバーを埋める供給源が設計として閉じている）ため、展開しても得るものが無い、という固有の事情による

## 却下した案

- **保存値だけ直す**（config の `sidebarOpen` を落とす）: 症状は消えるが、次に最大化中トグルすれば同じ状態へ戻る
- **狭幅でもトグルを永続化する**: 触れない保存値は解消するが、2つの形・二重レンダー・幅連動はそのまま
- **既定だけレール（現状維持）**: 背景1のとおり、展開でしかできないことが無い
- **レール単体でも畳めるようにする**: #245 の一括畳みと重複する
- **アイコンのみのレールへ縮める**: ADR 0018 の却下を維持（行き先アイコンはラベル無しでは伝わらない）
- **既存 config の移行コードを書く**: リリース前につき不要（残った `sidebarOpen` / `sidebarWidth` は読まれないだけ）

## 実装

`app/src/renderer/src/components/ui/sidebar.tsx`（shadcn fork＝状態・トリガー・レール・モバイル分岐の撤去）、`app/src/renderer/src/shell/LeftSidebar.tsx`（二重レンダーの1本化）、`app/src/renderer/src/shell/AppShell.tsx`（開閉状態と幅の配線の撤去）、`app/src/renderer/src/services/panel-width-pref.ts`（インスペクタ専用へ）、`app/src/main/ipc-config.ts`・`ipc-payloads.ts`（pref キー2つの撤去）、`app/src/renderer/src/backup/BackupStatus.tsx`（レール表示）。

受け入れ条件は `e2e/flows/sidebar-rail.spec.ts`（「展開する手段が無い」＝Ctrl+B・トリガー・ドラッグ縁・720px への縮小のいずれでも形が変わらないこと）と `e2e/flows/shell-axes.spec.ts`（レールの軸）が持つ。
