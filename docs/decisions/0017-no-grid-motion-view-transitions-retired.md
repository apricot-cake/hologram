# 0017. グリッドの切替はすべて即時にし、View Transitions を使わない

- 状態: 採用（2026-07-30）
- 関連: #252・[0014](0014-motion-is-css-view-transitions-only-for-grid-density.md)（置き換え元）・#19（モーションライブラリの棄却）・[0021](0021-panel-toggles-are-instant.md)（同じ物差しをサイドバー・詳細パネルへ広げた後続）

## 背景

[0014](0014-motion-is-css-view-transitions-only-for-grid-density.md) は View Transitions の適用面を「グリッドの密度切替だけ」に確定させ、起動を React 島側へ移した。その後、同じ検討の流れでカードの入場アニメ（スタガー）が廃止され、残ったグリッドの演出は密度切替のモーフ1つになった。

そこで残る1つの必要性が問われた。入場アニメと違い、このモーフに害は無い——明示操作のときだけ走り、切替自体は同期で終わり、失敗しても即時切替に落ちる。つまり純粋な飾りであり、あるかないかは好みだけで決まる。

## 決定

**グリッドのビュー/密度切替もすべて即時とし、View Transitions は使わない**（2026-07-30 ユーザー判断）。レンダラに `document.startViewTransition` の呼び出し箇所は無くなり、モーションは CSS（tw-animate のキーフレーム＋Base UI の状態属性 transition）だけになる。

判断材料:

- 密度切替のモーフは機能に何も足さない飾りで、対象の操作はまれ＝総価値が小さい。
- Chrome 公式ドキュメントの例示（サムネイル→詳細・固定ナビ・絞り込みでの並び替え）に**ビューモード切替は含まれない**（2026-07-30 確認）＝この面への適用は教科書例ですらない。デスクトップの参照群（Explorer・Lightroom 等）はビュー切替を即時で行う認識（未検証）。
- 再設計のトーン（抑制・静けさ・中身主役）とは「無い」方が整合する＝入場アニメ廃止と同じ物差し。
- この API の失敗は全て無言（例外なし・演出だけが消える）で、「動いているか」を確かめる専用の検証層とテストを維持し続ける必要があった。使わなければその監視責任ごと消える。

#19 のモーションライブラリ棄却は**引き続き有効で、根拠はむしろ単純になる**＝「CSS で足りる」。再訪条件（ジェスチャ連動演出の採用時）も変わらない。

## 影響

- 撤去したもの: `_shared/view-transition.ts`（起動ヘルパ＝flushSync・重複名検査・reduced-motion 分岐）・`_shared/density-transition.ts`（可視カードへの名前付け）・その単体テスト・`globals.css` のトークン接続（`::view-transition-*`）・legacy シートの `view-transition-name` 宣言と `::view-transition-*` 規則一式（モード切替時の透け対策の z-index 固定を含む＝遷移が走らなければ発生しない症状）・コマンドパレット用のランナー登録（`registerViewTransitionRunners`）・投稿者カードの `data-key`（名前の素としてだけ存在した）。
- 密度切替ハンドラの再描画は「1ペイント遅延」（押したボタンを先に描く楽観パターン）へ戻した＝同期化は View Transitions のキャプチャ都合だった。
- 0014 の実装で得た知見（起動の同期性・名前の一意性・スナップショットの伸縮）は 0014 本文に記録済みのまま残す。実装を復元する場合は #252 と PR #509/#520/#527/#532 を参照。

## 却下した案

- **密度切替のモーフを残す**: 実害は無く維持コストも支払い済みだったが、価値が好みに尽きる以上、所有者の判断で不採用。
