# 0007. タブは上部水平に置く（縦タブを採らない）

- 状態: 採用（2026-07-14）
- 関連: #154 / #148

## 背景

Hologram は「ライブラリを並べて見る道具」と「タブで複数の場所を行き来する道具」の雑種で、タブの置き場に前例がそのままは使えない。縦タブ（左カラムに縦積み）を採るかを検討した。

## 決定

**上部水平タブ**。あわせて幅の規律を対称に決める＝**左右のパネル（サイドバーとインスペクタ）は幅が競合したら畳むか被せる。中央のグリッドが優先。タブは常に水平。**

サイドバーに置くのは**場所**（フォルダ・コレクション・保存した検索）だけで、**述語**（メディア種別・プラットフォーム等の絞り込み）は上部のフィルタバーに置く。

## 理由

1. **ツリーとタブを両方持つ実プロダクトは全て「左ツリー＋上部水平タブ」**（Zotero・Obsidian・VS Code・Photoshop・Figma・Notion）。縦タブは永続的なツリーを持たないブラウザの作法で、ツリーを持つ製品が縦タブを使う例（JetBrains）でも、ツリーの列に混ぜず別の第二レールとして立てている。
2. **横幅が争奪資源**。狭い幅ではインスペクタを被せ表示に落とすほど横幅が足りない。縦タブは左カラムを最も広く持続的に占有するので最も不利で、水平タブは横幅をゼロしか使わない。

## 却下した案

**縦タブ**。上記2点による。将来必要になれば「第二レール」として別に立てる案は残す（ツリーには混ぜない・グリッドの横幅が対価）。

## 補足：「サイドバーがスカスカ」は却下の理由にならない

**この節の判定は [ADR 0018](0018-labeled-navigation-rail-default.md) により置き換え済み**（#678・2026-07-31）: 空白の解消策を「非問題」の判定から「資源側（既定をラベル付きレールへ縮める）」へ移した。**このADRの決定本体（水平タブ・縦タブの却下）は不変**——置き換わったのはこの補足節だけ。

縦タブ案の動機の1つがこれだったが、非問題と判断した＝①使うほど育つ（フォルダのリネーム→保存した検索→階層化がその道具・#42→#40→#41）②既定の種（すべて・最近・未分類などの名前付き場所）を置くので空にはならない ③薄いときは自動で畳む（インスペクタと同じ閾値で）。

## 未実装の追加決定

タブ帯を全幅トップ帯からコンテンツ列の中へスコープする改良（Obsidian 型・サイドバーはタイトルバー帯まで伸ばす）は 2026-07-18 に決定したが未実装。#154 / #148 が持つ。
