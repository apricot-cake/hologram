# 0028. 起動時に configDir・保存先の実パスを検査し、仮想化リダイレクトを検出する

- 状態: 採用（2026-08-07）・**#232 が着地し、`configDir()` の Windows既定は `%APPDATA%\Hologram` へ移った（2026-08-07）**
- 関連: #1009／前提＝#1003（MSIX 仮想化が今は起きていないことの実測）／この決定を前提として要求していた側＝#232（config を `%APPDATA%\Hologram` へ戻す設計・着地済み）

## 背景

2026-06-23、MSIX パッケージ内から駆動された子プロセスの `%APPDATA%`/HKCU 書き込みが、OS のストレージ仮想化によって private な per-package `LocalCache` へ静かにリダイレクトされ、約9082件のライブラリが実体の見えない場所へ積まれた。失敗モードは「保存はエラーを返す」ではなく「保存したのに一覧に出ない」で、気付いた時点で既に大量のデータが分岐先にあった（`native-host/paths.mts` の冒頭コメントに詳細）。

この事故を受けて Windows の `configDir()` は `%APPDATA%` を避け、ホームディレクトリ直下（`~/.hologram`）を使うよう変更された。2026-08-06（#1003）、この回避が今のホスト環境（Claude Code 本体）では不要になったことを4経路の実測で確認した — が、これは「仮想化という機構が無くなった」のではなく「今のホストがたまたまパッケージの外にいる」だけであり、ホスト側の構成が変われば逆方向にも戻りうる。#232 は `configDir` を `%APPDATA%\Hologram` へ戻す設計を持っており、戻せば再び仮想化の対象範囲に入る。戻す前に、分岐が起きたことを検知する仕組みが要る。

## 決定

- **起動時（`app.whenReady()` の最初）に、`configDir()` と実効ライブラリパス（`getSaveFolder()`）それぞれについて、実パスが `\Packages\<pkg>\LocalCache\` へ解決されていないかを検査する**（`app/src/main/lib-storage-redirect-guard.ts`）。
- **検査手段は #1003 の実測手法そのもの**: 対象ディレクトリへ使い捨ての probe ファイルを書き、`fs.realpathSync.native()`（Windows では `GetFinalPathNameByHandle` 相当）でその**実パス**を取り、probe を消す。同一プロセス内の書き→読み比較では仮想化を検出できない（同じプロセスは常に自分自身の仮想ビューに一致するため）ので、OS に実パスを問い合わせる必要がある。
- **`\Packages\` と `\LocalCache\` の両方を含む場合だけ「リダイレクト」と判定する**。片方だけの一致（"Packages" という名のフォルダ等）は誤検出として扱わない。
- **検査自体の失敗（probe が書けない・realpath が例外を投げる等）は「リダイレクトを検出した」と別扱いにする**。ディレクトリが未作成の新規インストールや権限の問題は `check-failed` として起動を妨げない — 検査できなかったことと、問題を見つけたことを同一視しない。
- **リダイレクトを検出したら起動を止め、ブロッキングダイアログを出して `app.exit(1)` する**。ログ行だけにしない: 2026-06-23 の事故は警告が `main.log` に眠ったまま誰にも読まれなかった形で進行したため、「読まれない警告」は対策にならないと判断した。ダイアログには対象（設定フォルダ／ライブラリの保存先）ごとに、期待していた場所と実際の書き込み先の両方を表示する。

## 影響

- `native-host/paths.mts` は変更しない（`configDir`/`defaultLibraryDir` の実装はそのまま）。この ADR はその出力を検査する層を追加するだけ。
- #232（config を `%APPDATA%` へ戻す）は、この検査が入ったことでブロッキング状態を解除できる。**2026-08-07 に着地済み**＝`configDir()` の Windows既定は `%APPDATA%\Hologram`。移行コードは入れていない（リリース前で既存ユーザーが作者本人1台のみのため）。
- コストは probe ファイル1個の書き→realpath→削除で、起動時間への影響はミリ秒未満。

## 却下した案

- **`GetCurrentPackageFullName` でパッケージアイデンティティを直接問う**: 却下。ネイティブアドオンが要るうえ、「パッケージに属しているか」と「このディレクトリが仮想化されているか」は別の質問（パッケージ内でも仮想化されない構成がありうる）。症状（実パスのズレ）を直接見る方が正確。
- **書いた内容を読み返して比較する**: 却下。同一プロセスは常に自分自身の仮想ビューを見るため、この比較は原理的に一致し続け、検知にならない。
- **`%APPDATA%` の文字列（環境変数の値）を検査する**: 却下。仮想化下でも環境変数の値自体は変わらないため、検知にならない。
