# 0020. 高速トリアージモードはフルスクリーン Dialog・キューはクライアント側計算・undo は #235 のスタックを再利用する

- 状態: 採用（2026-07-31）
- 関連: #46（本体）・#161（誤操作対策の合流元）・#235（セッション内 undo/redo スタック）・#22（タグピッカーポップ＝TagField の資産）

## 背景

未タグ・未フォルダの投稿を1件ずつ大写しにし、単キーでタグ付け・フォルダ振り分け・スキップができる「受信箱ゼロ」フローを追加する。#46 は「1手 undo」を要件に持ち、2026-07-19 の訂正コメントで根拠を「Hydrus 追随」から「単キー連打フローの中では直前1手で足りる」に立て直した上で、実装時に #235（通常画面のセッション内取り消しスタック）との関係を確認するよう求めていた。#235 は本 Issue 着手時点で「操作単位の取り消し」（トースト＋Ctrl+Z、投稿タグ・投稿者タグ・フォルダ所属が対象）まで実装済みだった。

## 決定

### 1. トリアージは #235 のスタックにそのまま乗せる

タグ付け・フォルダ振り分けは、通常画面の編集（`inspector-builder.ts`・`folders.ts`）と同じ `undo-builder.ts` の `pushUndo`（差分記録・`{target, added, removed}`）を呼ぶ。Ctrl+Z はトリアージ中も生きたままなので、同じスタックへ同じ形で積むのが素直。

トリアージの「Backspace で直前1手」は、この汎用スタックの**別レイヤー**として実装する（`services/triage.ts` の `lastAction: {kind, previousIndex, undo?}`）。理由:

- **キューのカーソルは undo スタックの知らない状態**。「スキップ」はデータを一切変えないので `pushUndo` に載せるものが無いが、トリアージの Backspace は「1件前の投稿に戻る」という体験を毎回提供する必要がある。
- **1手だけ・常に直前**という要件は、汎用スタックの「何手でも遡れる・トーストは最新のときだけ効く」という設計とは物差しが違う。トリアージ内の Backspace は自分の直前アクション1件だけを見る専用の状態を持ち、そのアクションがデータ変更を伴うときだけ #235 の `pushUndo` が返した undo クロージャを併せて呼ぶ。

結果として、トリアージ内の Backspace と Ctrl+Z は**同じデータ変更を別々の入口から取り消せる**（互いに矛盾しない・二重取り消しにもならない：Ctrl+Z 側は `undoIfTop` で「まだスタック最上段か」を見ている）。

### 2. キューは開いた瞬間のスナップショット、条件はクライアント側で計算する

「未タグ AND 未フォルダ」は `services/query.ts` の条件木には今のところ表現できない（`tag:__none` はあるが `folder:__none` に相当する葉が無い）。木に葉を足す拡張も検討したが、トリアージのキューは**保存・合成されるクエリではなく一回限りの内部フィルタ**なので、`postGrid.groupRecords(getAllPosts()).filter(g => !g.rep.tags.length && !isInAnyStaticFolder(g.rep.captureId))` をその場で計算するだけで足りる。木を拡張するコストと使い道（保存検索・チップ帯での再利用）が今回は無いため見送った。

キューは `openTriage()` の瞬間に1回だけ計算し、以後はその配列を順に進む（インスペクタが投稿の「スナップショット」を1件保持するのと同じ理由＝取り込み中にライブラリが動いても、作業中の並びが足元から入れ替わらない）。

### 3. 全画面 Dialog（AppShell の差し替えではない）

image-tab（グリッドを差し替える）と Lightbox（Dialog を丸ごとステージにする）の2つの前例があった。トリアージは Lightbox 側を選んだ: Dialog は Esc・外側クリック・フォーカストラップを無料で持ち、AppShell 側の `hidden` 分岐やレイアウトモード判定に触れずに済む。中身は `DialogPrimitive.Popup` を `100vw/100vh` で埋める不透明背景（スクリムではなく「これがページそのもの」という扱い）。

### 4. 数字キー（1-9）のクイックタグと手動ピン留め

#46 の 2026-07-11 コメントで「v1 から入れる」と確定していた機能。ピン留めは `AppPrefs.triagePinnedTags: string[]`（`main/ipc-config.ts` の許可リストに追加した通常の pref）に保存し、`services/triage.ts` が起動時に読み直す。ピン留め自体は取り消しスタックの対象外（データ編集ではなく個人の設定なので、Ctrl+Z で戻る対象にしない）。

## 影響

- `services/triage.ts`（純状態）と `services/triage-builder.ts`（deps 注入・実際の書き込み）に分離。既存の `undo-builder.ts` / `folders.ts` / `posts.ts` をそのまま消費し、タグ・フォルダの書き込み経路を増やしていない。
- コマンドパレット（`cmd:triage-start`）とツールバーの常設ボタン（バッジは未整理件数）の2つの入口を持つ。

## 却下した案

- **`query.ts` に `folder:__none` 葉を足してキューを表現する**: 保存検索・チップ帯での再利用価値が今回無く、木を触る分だけ影響範囲が広がるため見送った（再検討の余地はある＝「未整理」をサイドバーの常設フィルタにする話が別に出たら、その時点で足す）。
- **トリアージのタグ入力に `inspector/TagField.tsx` をそのまま使う**: キューの投稿は構造上つねに無タグなので、チップ表示は毎回空になる（TagField が主に解決する「今の値との差分表示」のうまみが無い）。語彙候補ポップアップだけが使いたい部分だったので、v1 はプレーンな入力に留め、語彙サジェストは follow-up とした。
- **通常画面の undo スタックに「トリアージのスキップ」も記録する**: スキップはデータを変えないので、汎用スタックに積む差分が存在しない。トリアージ専用の `lastAction` がこのケースをそのまま吸収する。
