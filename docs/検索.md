# 検索

投稿の正本はSQLite、検索索引はローカルのMeilisearchに保存する。アプリが公式Windowsバイナリを起動し、ループバック接続と起動ごとの認証鍵を使う。外部の検索サービスへ投稿を送らない。

索引は設定ディレクトリの `search-v1` に置き、ライブラリの絶対パスから索引名を分ける。検索前にSQLiteの現在の内容と照合し、追加・更新・削除の完了を待ってから検索する。プロセス起動後の初回は正本から再構築する。

通常検索、全文検索、投稿者検索、検索候補はMeilisearchを使う。全文検索は一致箇所とエンジンの順位を表示する。通常の投稿一覧は検索結果の全IDを受け取り、既存の条件木と並べ替えを適用する。件数上限で切った検索結果に後からフィルターをかけない。AND・OR・否定・フォルダ所属は既存の条件評価を共有する。

全検索語を要求する `matchingStrategy: all` を使う。誤字許容は5文字以上で1文字、9文字以上で2文字。数字と投稿者ID（引用情報内を含む）の誤字補正は無効にする。前方一致は維持するため、IDの検索は完全一致フィルターではない。検索候補ではIDを表示名・その他のキーワードと別の属性に渡す。候補から選んだタグ・投稿者の条件は既存の厳密な照合を維持する。

順位規則は `words, typo, proximity, exactness, attribute, sort`。語数・誤字数・語の距離が同条件なら、単語の完全一致を項目の優先度より先に評価する。項目はタグ・ハッシュタグ・タイトル類・投稿者名/ID・本文・代替テキスト・引用情報・リンクカード・投票の順を優先する。通常一覧は利用者の並び順を維持し、全文検索と検索候補では検索順位を使う。

索引と検索語はNFKCで正規化し、全角・半角や互換文字の違いを吸収する。正本と表示する原文は変更しない。一致位置は正規化後のUTF-8位置から原文の書記素単位へ戻す。言語は自動判定を維持する。URL照合は正規化済み投稿キーと文字列一致を維持する。日本語の漢字と読みの同一視は含めない。言語の自動判定や語の分割により、任意の部分文字列が必ず一致するわけではない。

## 配布と移行

`scripts/prepare-meilisearch.mjs` が固定バージョンの公式バイナリを取得し、SHA-256を検証する。開発ビルドと配布版の両方で同じバイナリを使う。

SQLiteのバージョン48から49への変換は、アプリを終了して `node scripts/convert-search-index.mts <hologram.db>` を実行する。バックアップ後に旧FTS索引だけを削除する。投稿・メディア・タグのレコードは変更しない。
