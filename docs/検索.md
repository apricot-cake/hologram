# 検索

投稿の正本は SQLite、検索索引は端末上で動かす Meilisearch に保存します。アプリは公式の Windows バイナリを起動し、ループバック接続と起動ごとに作る認証鍵を使います。投稿データを外部の検索サービスへ送ることはありません。

索引は設定ディレクトリの `search-v1` に置き、ライブラリの絶対パスごとに索引を分けます。検索前には SQLite の現在の内容と照合し、追加、更新、削除を反映してから検索します。アプリの起動後に最初に使うときは、正本から索引を再構築します。

通常検索、全文検索、投稿者検索、検索候補には Meilisearch を使います。全文検索では一致箇所と検索順位を表示します。通常の投稿一覧は、検索で得た全 ID に既存の条件と並び替えを適用します。件数上限で切った検索結果に、後からフィルターを適用しません。AND、OR、否定、フォルダ所属は既存の条件評価を共有します。

全検索語を要求する `matchingStrategy: all` を使います。誤字許容は 5 文字以上で 1 文字、9 文字以上で 2 文字です。数字と投稿者 ID は誤字補正しません。ID 検索では前方一致を維持するため、完全一致だけに絞りません。候補から選んだタグ・投稿者の条件は既存の厳密な照合を使います。

順位規則は `words, typo, proximity, exactness, attribute, sort` です。同条件では、単語の完全一致を項目の優先度より先に評価します。項目はタグ、ハッシュタグ、タイトル類、投稿者名と ID、本文、代替テキスト、引用情報、リンクカード、投票の順に優先します。通常一覧は利用者が選んだ並び順を保ち、全文検索と候補では検索順位を使います。

索引と検索語は NFKC で正規化し、全角・半角や互換文字の違いを吸収します。正本と表示する原文は変更しません。一致位置は正規化後の UTF-8 位置から原文の書記素単位へ戻します。言語は自動判定を維持します。日本語の漢字と読みを同一視する検索は行いません。言語の自動判定や語の分割によっては、任意の部分文字列が一致しないことがあります。

## 投稿者の以前の名前

投稿者検索と検索候補は、現在の名前に加えて以前の表示名・ユーザー名も対象にします。候補から投稿者を選ぶと、その投稿者の投稿を表示します。カードの旧名表示は旧名で検索したときだけです。投稿者インスペクタでは名前とユーザー名を上部にまとめ、その直下・サイトの直上に以前の名前とユーザー名を常時表示します。履歴がある項目だけを、サイト・投稿数と同じラベル列・値列に並べます。最終確認日は各旧名のツールチップで確認できます。

名前はサービスと固定IDの組み合わせに紐づけ、保存時に取得した情報から記録します。IDのないハンドルだけの情報から履歴を推測しません。初回移行では既存投稿とプロフィールに残る名前を取り込みます。最終確認日は変更日ではなく、その名前を取得した記録の日時です。以前の名前に戻った場合は、その名前を現在名として扱い、履歴表示から外します。

履歴はSQLiteの `poster_names` に保存します。完全エクスポートの `poster-profiles.json` にも含め、取り込み時には現在のプロフィールを優先しつつ履歴を統合します。名前を確認するための定期巡回や追加通信は行いません。

## 配布と移行

`scripts/prepare-meilisearch.mjs` は固定バージョンの公式バイナリを取得し、SHA-256 を検証します。開発ビルドと配布版は同じバイナリを使います。

SQLite のスキーマ 48 を 49 へ移行する必要がある場合は、アプリを終了して次を実行します。

```powershell
node scripts/convert-search-index.mts <hologram.db>
```

コマンドはデータベースのバックアップを作ってから旧 FTS 索引だけを削除します。投稿、メディア、タグのレコードは変更しません。48 と 49 以外のスキーマには使えません。
