# 表示言語を保守する

Hologram は、アプリと Chrome 拡張機能の両方で日本語と英語を提供します。新しい UI 文言は、片方だけを翻訳して出荷しません。

アプリでは設定から言語を選べます。`auto` は OS の表示言語に従います。拡張機能は Chrome の表示言語に従います。

## 翻訳を変更する

数、日時、固有名詞は、対象の言語で自然に読める表現を優先します。直訳のために語順や情報のまとまりを崩さないでください。

アプリの文言は `app/src/renderer/src/services/locales/{ja,en}.ts` にあります。i18next と ICU MessageFormat を使うため、差し込みは `{name}`、複数形は `{count, plural, one {...} other {...}}` の形式で書きます。呼び出し側は `t('posterPosts', { count, formattedCount })` のように、意味のある名前で値を渡します。`count` には数値、`formattedCount` には省略表記などの表示用文字列を渡します。

拡張機能の文言は、ページ内 UI では `extension/utils/i18n.ts`、Chrome 本体の UI では `extension/public/_locales/{ja,en}/messages.json` にあります。ページ内 UI の差し込みは `$1`、`$2` の形式です。Chrome のメッセージでは `messages.json` の `placeholders` を定義し、`message` から参照します。既存の `description` と `placeholders` は翻訳の文脈を伝えるため、削除や改名をしません。

ICU の書式は [i18next-icu](https://github.com/i18next/i18next-icu)、Chrome のメッセージ形式は [Chrome のローカライズ仕様](https://developer.chrome.com/docs/extensions/how-to/ui/localization-message-formats) に従います。

## 変更時の確認

UI テキストを追加、削除、変更するときは、次を同じ変更に含めます。

1. アプリの日本語と英語のリソースを更新する。
2. 拡張機能に同じ文言がある場合は、日本語と英語を同時に更新する。
3. 置換する値、複数形、文の意味が両言語で対応していることを確認する。
4. 表示言語の解決を変える場合は、実際の表示言語と `lang` 属性を一致させる。
5. 追加したキーと差し込み項目をテストで検査する。

`lang` 属性を表示言語と一致させるのは、支援技術が言語を判定できるようにするためです。[WCAG 2.2 SC 3.1.2](https://www.w3.org/TR/WCAG22/#language-of-parts) を参照してください。

## 検証する

次を実行します。

```powershell
npm run check:ext
```

続けて、アプリの設定、OS の言語を使う `auto`、Chrome の表示言語で、それぞれの画面が意図した言語になることを確認してください。
