# verify-extension — 拡張の変更を実ブラウザで確かめる

正本は `docs/build.md`「拡張機能の開発・配布」。矛盾があればそちらが勝つ。

## 土台: ブラウザを2つに分ける

| ブラウザ | 読む出力 | 誰のもの |
| --- | --- | --- |
| **開発用**（専用プロファイル `~/.hologram-ext-profile` の Chrome を**ユーザーが起動**） | `chrome-mv3-dev` | 開発とログイン込みの実機確認 |
| **日常の Chrome** | `chrome-mv3`（production） | ユーザーが普段 Hologram を使う方。触らない |

**dev 出力を日常の Chrome へ読み込ませない。**開発モードの拡張は manifest に `content_scripts` を持たず dev サーバー接続経由で実行時登録するので、サーバーが止まると普段使いの拡張ごと沈黙する（2026-07-26 被弾）。

**開発用ブラウザを自動化スタックで起動しない。**web-ext / chrome-launcher / Playwright 経由の起動は自動化フラグの指紋が付き、X・Google がボット判定してサインインを弾く（2026-07-26 実測）。起動コマンドと初回セットアップは docs/build.md。ホットリロードは拡張⇔dev サーバー間の機構＝人が起動したブラウザでもそのまま効く。

## 手順（既定）

1. 作業ツリーの `extension/` で dev サーバーを起動（fresh worktree は先に `npm install`）。**worktree からそのまま起動してよい**＝本体ツリーを経由する必要はない（開発用ブラウザは dev サーバーが指す出力を読むだけ）。

   **Claude が起動する時は標準入力を開いたまま**にする＝WXT は起動後に「Press o + enter」で stdin を待つ対話モードに入り、`npm run dev:ext` を素で背景実行すると **EOF を読んで即終了し、開いたブラウザごと落ちる**（2026-07-26 実測）。

   ```
   tail -f /dev/null | npm run dev:ext
   ```
2. ユーザーが開発用ブラウザを起動する（docs/build.md のコマンド）。プロファイルは永続＝サインインは初回だけ。
3. **ソースを直したらホットリロードに任せる**。手動で拡張もページも再読み込みしない。
4. **Claude の自動確認は使い捨て環境で行う**＝`scripts/lib-extension-e2e.cts` 系（同梱 Chromium・一時プロファイル・モック native host。`npm run test:e2e-extension` / 実サイトカナリアは `e2e-capture-test.cts`）。Playwright はポート未指定ならパイプで喋るのでどこにも listen しない。
   **ログイン済みアカウントでの挙動は自動化しない**＝この拡張は「X から自動化に見えないこと」を設計原則に持ち（#362）、同じ制約が検証にもかかる。自動化スタックからのサインインはボット検知にも当たる（2026-07-26 実測）。ログインが要る確認は人間が開発用ブラウザで行い、Claude は結果・スクショを受け取る。
5. 人でないと不可能な操作（ログインが要る確認・実キー入力・初回サインイン）だけユーザーへ依頼する。

## 日常の Chrome へ変更を届ける時

機能が仕上がってユーザーが普段使いで試す段になったら、その時だけ:

1. `npm run build:ext` → `.output/chrome-mv3`
2. worktree で作業していれば、本体ツリーの同じパスへ上書きコピー（日常の Chrome が読むのは本体側）
3. `chrome://extensions` でリロード1回＋対象タブの再読み込みを依頼（拡張リロードでは既存タブへ再注入されない）

manifest やビルド内容の検算は渡す前に自分で済ませる＝`content_scripts` があるか・`commands` が揃っているか・変更した識別子がバンドルに実在するか。

## Claude から見えないもの（実測 2026-07-26）

- **`chrome://` ページは開けない**（ツールが明示拒否）。**`chrome-extension://` は開けるが読めない**（別拡張のページに JS を差せない）。拡張機能ページのエラー表示・リロードボタン・ショートカット割当画面はユーザーの領分。
- ただし**開発用ブラウザは CDP で見られる**＝上の制約は「日常の Chrome に何か起きた時」にだけ効く。そこで説明の付かない挙動に当たったら、当てずっぽうの操作依頼を重ねず `chrome://extensions` のエラー画面のスクショを1枚頼む。
- 「押しても何も起きないのが正常」な操作（拡張リロード等）を、成否を観測する手段のないまま依頼して往復しない。

## 罠

- **背景実行した wxt はログを一切残さない**＝生死はプロセス一覧、dev サーバーの接続可否は WebSocket を直接叩いて観測する。Node ≥17 は `::1` だけに bind することがあり、Chrome は `localhost` を IPv4 に解決して `ERR_CONNECTION_REFUSED` になる（`--host` で指定可）。
- **ビルド出力の grep は正規表現リテラルのエスケープで偽の空振りを起こす**。ソースの `/^\/i\/bookmarks(\/|$)/` はバンドル上も `i\/bookmarks` のまま＝`i/bookmarks` で grep すると 0 件になり「ビルドされていない」と誤読する。識別子（関数名・定数名）で探す。
- **拡張を削除→再追加すると `chrome.storage.local`（設定）とショートカット割当が消える**。リロードでは消えない。
- manifest に**後から追加したコマンドは既存インストールにキーが自動割当されないことがある**＝新ショートカットが効かない時は `chrome://extensions/shortcuts` の確認を頼む。
- **x.com は非表示タブで画像を読み込まない**＝背景タブで DOM を見て「画像が無い」と判断しない（2026-07-26 に丸ごと無効な調査をした）。`document.visibilityState` を先に見る。
