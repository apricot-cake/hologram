# progress-check — 全体の現在地を取り直して次を流す

このスキルは**手順**だけを持つ。着手順そのものは持たない（順序の出所はユーザーの口頭指示という私的文脈なので、リポジトリの外＝Claude のメモリ `hologram-priority` にある）。Issue の様式・Status の値・着手候補の選び方は skill `issue-style` が正。共有資源の線引きは `docs/build.md`「検証ルール」が正。

## 1. 実態を取り直す（記憶や前回の記録から始めない）

前回セッションの記録・Issue の Status・メモリの但し書きは、**書かれた時点の宣言であって現在の実態ではない**。毎回ここから始める。

```bash
git fetch --prune && git status --short && git worktree list && git branch -a
gh pr list --state open --limit 30 --json number,title,isDraft,mergeStateStatus,headRefName
```

並行セッションは `list_sessions` で見る（`isRunning` と cwd／branch まで見る。取得できなかった状態を「稼働なし」と報告しない）。

ボードの Status は `gh project item-list 3 --owner "@me" --limit 400 --format json`。ブロック中の一覧は `gh issue list --state open --search "is:blocked"`。

## 2. 未着地を先に閉じる

新しい着手より、**幹へ戻っていないもの**が先。最終コミットから2日以上経っているブランチ、幹から数十コミット遅れている PR、PR の無い push 済みブランチを拾う。着地の遅れは待ち時間ではなく作業量に変わる（#41 の実例＝4日放置で main と86コミット差・9ファイル衝突）。

マージ済みブランチの掃除はグローバルの規約どおり確認なしで行う。

## 3. Dependabot の PR は「CI が緑」だけで判断しない

CI（`.github/workflows/ci.yml`）が回すのは `npm run check`＝lint / typecheck / test だけで、**パッケージング（`npm run dist`）も拡張の実機動作も一切踏まない**。緑は「その領域を確かめた」を意味しない。

マージ前に2つ見る。

1. **この更新を CI は実際に踏むか。** 踏まない領域（electron-builder・配布・拡張のビルド）なら、手元で該当経路を走らせてから判断する。
2. **その依存を名指しした Issue が open で無いか。** 2026-07-28 に #394 が「electron-builder 系の更新 PR 5本は個別にマージせず本 Issue の作業で一括して解消する」と明記していたのに、CI が緑だからと #420 を単独マージした。照合が事後になったのが原因。

## 4. 並列に出せるかは「共有資源」で決まる（ファイルの衝突ではない）

コードの衝突は「同じファイルか」ではなく**同じ行を書くか**で見る。ただし実際に並列数を縛るのはコードではなく、worktree で隔離できない資源のほうで、それぞれ**同時に1セッションだけ**。

- **実機 Chrome ＋ 拡張のリロード**（本体ツリーの `.output/chrome-mv3` は1本しか流せない）
- **起動中のアプリ**（見た目の確認・実 IPC を使う検証）
- **本番の Native Messaging host**

3枠が埋まったら、コードが衝突しない Issue が残っていても6本目は待ちを生むだけ。docs だけ・依存区分だけ、のように検証を要さないものが残っていればそれを充てる。

## 5. Issue の読み方（ここで2回間違えている）

- **本文だけ読まない。** 設計は後から付いたコメントで確定していることが多く、本文の「未決事項」がコメントで閉じている例が複数ある（#292＝置き場所は「DB 内の圧縮原本テーブル」で確定済み・#264＝列構成と初期収録語が確定済み）。`gh issue view <n> --comments` で読む。
- **`gh project item-list --format json` は日本語のフィールド名（キー）を壊す。** 値は無傷なので、キーは名前で引かず末尾一致で拾う（`Object.keys(it).find(k => k.endsWith('先度'))`）。`gh api graphql` は壊さないので、厳密な同定が要る時はそちら。

## 6. 状態をここに書き足さない

「いま何が走っているか」「どの PR が緑か」は次のセッションでは必ず古い。**書き留めず毎回 1. で取り直す**。このスキルに足してよいのは、取り直し方と、取り違えた時の直し方だけ。
